## How this work is done

- **Everything is proven on the real card, never a simulation.** Adrian's card is
  `lw-b0fe81f61b44` at `192.168.18.70` (find it with a subnet sweep — see below).
  41 lights on **GPIO 18**, colour order **RGB**, WS2815.
- **Dev server on 9999**: `cd lightweaver && npm run dev -- --port 9999 --strictPort`.
  Playwright needs the shell sandbox disabled on this Mac or Chromium dies with a
  mach-port error.
- **Drive the real browser through Playwright, not the Chrome extension.** The extension
  wedges. Headless Playwright against `192.168.18.70` works reliably and screenshots are
  how you actually see the UI.
- Pipeline: **Fable plans → DeepSeek (`opencode run --auto -m opencode/deepseek-v4-flash-free
  --dir <repo> -f <brief>`) executes, parallelised by file → Opus verifies.** Never trust a
  DeepSeek claim; check the tree and run the tests. The free endpoint 503s constantly —
  wrap every call in a retry loop that checks for the actual file change.
- **This repo uses `node:test`, NOT vitest.** `npm run test:unit`.

## What works now

- Bare `/` lands on **Setup** — a nine-step ladder that derives its position from live card
  state. One step open at a time; finished steps collapse to one line with **Change**,
  which reopens that step in place.
- **Find my card** sweeps the network when every remembered address is stale (routers move
  leases). Proven: two wrong addresses, card found in 3s.
- Port picker is a **grid of buttons** — press one to light it, tick "Lights are installed
  on GPIO n". Firmware re-announces its mDNS name every 2 min (flashed to the card).
- **Colour reorder**: the strip paints red/green/blue blocks, you drag three chips into the
  order you actually see, and it works out the true wiring. Confirmed on hardware.
- **Counting ruler**: every 10th light green, count in tens, type the number. Confirmed.
- One shared install path, `src/lib/cardSetupDeploy.js` — its header comment lists every
  hardware failure it answers. Use it for ALL card writes.

## The blocker to fix first

**G10 — clicking a pattern does not change the physical lights, silently.**
`lw-pattern.jsx` gates preview on `authorizedPatternCardAccess`, which requires the card's
`projectId` + `projectFingerprint` to match the open Studio project. When they differ the
click is a no-op with no message. Adrian hit this repeatedly.

His instruction, verbatim in substance: *"I should be loaded on the project that is on the
card. You shouldn't tell me I'm on a different piece. You should know what piece I'm on and
have it inside of this."* The card is the authority; Studio must adopt its identity, not ask
the owner to reconcile.

Partly done: `adoptWiringFromCard` in `src/v3/lw-setup.jsx` now takes the card's wiring AND
sets `projectId` from the card. **Not yet verified on hardware.** Remaining:
- Verify a pattern click moves the lights after adoption.
- Adopt on EVERY screen, not just Setup — the Patterns screen should never be the place
  this is discovered.
- Make any remaining refusal visible with a one-tap fix, never a dead click.

- **Firmware can wedge** at `"prior promotion cleanup failed"` — only

- **`lightweaver.local` still does not resolve** from macOS even after the re-announce fix.

  covers it — but the name path is still broken.
- **Microphone has zero firmware support.** No I2S, no audio ADC. Sound-reactive only works
  while a browser tab streams. Say so plainly; do not imply it works standalone.
- **Steps 9, 10, 11 never walked as an owner** — layout, save/load, knobs. Their surfaces
  exist and were probed, but nobody has used them.

## Hard-won rules — do not relearn these

1. **A button that only SHOWS something must never change anything.** A probe that rewrote
   the card's setup moved Adrian's output to a port with no strip on it.
2. **"I cannot find your card" is never "your card is new."** That single wrong assumption
   told him to flash a working card, join a hotspot that does not exist, and start over.
3. **The card's own report is the only proof.** Reconnect watchers time out long before a
   healthy card finishes booting; their timeout is not the outcome.
4. **Staging must be activated AND confirmed** or the card silently rolls back ~90s later.
5. **Never offer "clear the card and start over"** as the way out of a mid-walk refusal.
6. **Defaults are not answers.** A fresh project ships `colorOrder: 'RGB'` and wiring on
   GPIO 16 with 44 lights; both were being treated as the owner's answers.
7. **`addInitScript` re-runs on every navigation** — clearing storage in it makes any
   reload-recovery test unreachable.
8. **Several Studio tabs on one card wedge the renderer.** Keep one.
